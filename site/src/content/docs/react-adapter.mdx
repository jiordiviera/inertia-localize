# React adapter

`@inertia-localize/react` reads the current Inertia `i18n` prop directly — it does not keep a
second locale or message dictionary in React state.

```tsx
import { useTranslation } from '@inertia-localize/react'

export function Greeting() {
  const { t, locale, locales } = useTranslation()

  return (
    <p lang={locale}>
      {t('greeting.user', { name: 'Ada' })} ({locales.length} languages)
    </p>
  )
}
```

`useTranslation()` returns:

| Field | Type |
| --- | --- |
| `t(key, replacements?)` | Looks up a dot-key message and interpolates `:placeholder`s |
| `tChoice(key, count, replacements?)` | Selects a plural form using Laravel's `trans_choice` syntax — see [Interpolation](/docs/interpolation) |
| `locale` | Active locale code |
| `fallback` | Configured fallback locale code |
| `locales` | Every supported locale, as `{ code, name }` |

The consuming app must install compatible versions of `react` and `@inertiajs/react`.

## Switching locale

```tsx
import { useLocaleSwitch } from '@inertia-localize/react'

const { setLocale, switching } = useLocaleSwitch()
```

Posts to the locale-switch route (`/locale` by default, override with `{ url }`) via Inertia's
`router.post()`; the redirect it triggers refreshes `i18n` like any other visit. Also takes
`preserveScroll`, `preserveState`, `onSuccess`, and `onError`.
