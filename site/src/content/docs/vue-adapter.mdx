# Vue adapter

`@inertia-localize/vue` reads the current Inertia page props directly and requires no Vue
plugin — just call the composable inside `<script setup>`.

```vue
<script setup lang="ts">
import { useTranslation } from '@inertia-localize/vue'

const { t, locale, locales } = useTranslation()
</script>

<template>
  <p :lang="locale">
    {{ t('greeting.user', { name: 'Ada' }) }}
    ({{ locales.length }} languages)
  </p>
</template>
```

`useTranslation()` returns `t(key, replacements?)`, `tChoice(key, count, replacements?)` (Laravel
`trans_choice` syntax — see [Interpolation](/docs/interpolation)), plus computed refs for
`locale`, `fallback`, and `locales` — the same shape as the [React adapter](/docs/react-adapter),
so messages and dot keys behave identically across both.

The consuming app must install compatible versions of `vue` and `@inertiajs/vue3`.

## Switching locale

```vue
<script setup lang="ts">
import { useLocaleSwitch } from '@inertia-localize/vue'

const { setLocale, switching } = useLocaleSwitch()
</script>
```

Same shape as the [React adapter](/docs/react-adapter): posts to `/locale` by default (override
with `{ url }`) via Inertia's `router.post()`, plus `preserveScroll`, `preserveState`,
`onSuccess`, and `onError`. `switching` is a computed ref here instead of a plain boolean.
